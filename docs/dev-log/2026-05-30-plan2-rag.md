## 핵심 의사결정 (Plan 2)

### D-1. Embedder를 Protocol로 추상화

- **상황**: spec §4.3은 BGE-M3 default + Voyage-3 교체 가능 명시.
- **결정**: `Embedder` Protocol(`embed`, `embed_query`, `dim` 속성) + `BGEM3Embedder`(default) + `FakeEmbedder`(테스트용 SHA-256 기반 결정론).
- **근거**: BGE-M3 무게(~2.3GB)를 unit test에 끌고 들어가지 않음. 동시에 Voyage/OpenAI 교체 가능성을 코드 레벨에서 미리 보장.
- **면접 답변**: "embedding 백엔드를 Protocol로 추상화. BGE-M3는 한국어 RAG에서 검증된 multilingual 모델이지만, 비용·지연·라이센스가 바뀌면 Voyage-3로 한 줄 교체 가능."

### D-2. BGE-M3 lazy load + `# noqa: PLC0415`

- **상황**: `from sentence_transformers import SentenceTransformer`는 torch + tokenizers 등 무거운 import 체인을 트리거.
- **결정**: `BGEM3Embedder._load()` 메서드 안에서 lazy import. 단 ruff PLC0415(imports must be top-level)에 명시적 `# noqa: PLC0415` + 인라인 주석으로 정당화.
- **근거**: 모듈 import 비용을 unit test 프로세스에서 제거. 첫 `embed()` 호출 시점에만 무거운 import.
- **면접 답변**: "테스트 환경에서 sentence-transformers의 ~1.5GB import 비용을 피하기 위해 lazy import 패턴 사용. ruff PLC0415 룰은 인라인 noqa로 정당성 명시."

### D-3. 모든 PDF→chunks 중간 산출물을 jsonl로 디스크에 남기기

- **상황**: 임베딩 모델/토픽 카탈로그/청크 사이즈 등이 바뀔 때마다 전체 PDF 재추출은 비효율.
- **결정**: `data/extracted/<source>.jsonl` (pdfplumber 결과) → `data/chunks/<source>.jsonl` (clean + chunk + tag 결과) → ChromaDB. 임베더 교체 시 마지막 단계만 재실행 가능.
- **면접 답변**: "파이프라인의 모든 중간 산출물을 jsonl로 남겨, 임베딩 모델을 BGE-M3 → Voyage-3로 바꿔도 PDF 재추출/재청킹 없이 임베딩만 다시 계산하면 됨."

## 트러블슈팅 로그

### T-1. Subagent timeout — sentence-transformers + torch ~1.5GB 첫 다운로드

- **발생 시점**: Plan 2 Task 1 implementer subagent dispatch.
- **현상**: subagent가 14분 timeout에 걸려 "Waiting for uv sync to finish in background" 보고 후 종료. 그 동안 `uv sync`는 sentence-transformers, torch, transformers, chromadb 등 wheel을 받는 중.
- **해결**: controller가 직접 `uv sync` 다시 실행 → 86초로 마무리(앞서 받은 부분은 캐시). 나머지 step(ruff/mypy/pytest/commit)을 controller가 직접 처리.
- **교훈**: 무거운 첫 install이 포함된 task는 subagent timeout(15분) 위험. controller가 fallback으로 받아 처리하는 패턴이 유효.
- **포트폴리오용 1줄**: "약 1.5GB 의존성 첫 설치로 인한 14분 timeout을 controller fallback으로 회수해 14분 손실을 86초로 단축."

### T-2. PLR2004 magic number — 테스트 코드 반복 패턴

- **발생 시점**: Tasks 1, 2, 4, 5 모두에서 발생.
- **현상**: `assert len(out) == 8`, `assert chunks[0].metadata.page == 1` 같은 라인에서 ruff PLR2004 발화.
- **해결**: `expected_dim = 8`, `expected_page = 1` 같은 명명 지역변수 추출 후 비교.
- **교훈**: ruff strict 환경에서는 테스트도 magic number 금지. plan 작성 시 이 패턴을 lessons-learned에 미리 포함해 task별 시간 단축.
- **포트폴리오용 1줄**: "ruff PLR2004 strict 환경에서 테스트의 magic number도 정직하게 명명. Plan 문서의 lessons-learned 섹션으로 task 간 시간 단축."

### T-3. PLC0415 lazy import — 정당한 예외 케이스

- **발생 시점**: Task 5 BGE-M3 embedder.
- **현상**: lazy import(`from sentence_transformers import SentenceTransformer`)가 함수 내부에 있어 ruff PLC0415 발화.
- **해결**: 인라인 `# noqa: PLC0415` + 주석("`torch + transformers ~2GB are otherwise pulled at module import time`")로 정당화. 다른 곳에서는 `# noqa` 금지.
- **교훈**: 룰 위반의 정당성을 코드 옆에 명시. `# noqa` 남발은 strict 환경의 가치를 무너뜨림.

### T-4. mypy strict + reportlab no type stubs

- **발생 시점**: Task 4 PDF loader (reportlab을 test fixture에서 사용).
- **현상**: mypy strict 환경에서 `from reportlab.pdfgen import canvas` 등이 `Cannot find implementation or library stub` 에러.
- **해결**: `pyproject.toml`의 `[[tool.mypy.overrides]]`에 `module = "reportlab.*"` + `ignore_missing_imports = true` 추가. `# type: ignore` 코멘트는 사용하지 않음.
- **교훈**: type stub 없는 외부 라이브러리는 설정으로 처리. 개별 import 라인에 `# type: ignore`를 남발하지 않음.
- **포트폴리오용 1줄**: "mypy strict 환경에서 type stub 없는 외부 라이브러리는 `# type: ignore` 대신 `[[tool.mypy.overrides]]`로 처리해 코드 노이즈 0 유지."

### T-5. reportlab 한글 CID 폰트 등록

- **발생 시점**: Task 4 PDF loader test fixture.
- **현상**: reportlab 기본 폰트는 한글 미지원. 임의로 한글 그리면 빈 사각형.
- **해결**: `pdfmetrics.registerFont(UnicodeCIDFont("HYSMyeongJo-Medium"))` — reportlab 번들 CID 폰트로 ToUnicode CMap 임베딩. pdfplumber 추출 시 한글 round-trip 성공.
- **검증**: 테스트의 `assert "정규화" in pages[0].text`가 통과.
- **포트폴리오용 1줄**: "테스트 픽스처에서 reportlab CID 폰트(HYSMyeongJo-Medium) + ToUnicode CMap으로 한글 PDF를 합성, pdfplumber 추출 단계까지 round-trip을 단위 테스트로 검증."
